# ISOEdu 원투원 블로그 콘텐츠 제작 실습

## 목표와 결과물

실제 BNI 원투원 자료, 함께 찍은 사진, 대화 메모를 활용해 작성자와 상대방의 사업을 함께 소개하는 블로그 글 한 편을 완성한다. 글에는 각자의 전문 분야, 실제 대화, 작성자의 인사이트, 공개용 문의 경로가 담긴다. 발행 주소를 미팅 기록에 남기고 다음 만남에서도 반복한다.

실습 화면: `/practice/one-to-one` (홈 왼쪽 메뉴의 ‘원투원 블로그 실습’).

## 준비

- 사용할 외부 블로그의 회원가입과 로그인
- 나와 상대방의 원투원 양식 PDF 또는 PPTX 원본
- 함께 찍은 사진과 미팅 날짜
- 실제 대화를 적은 짧은 메모
- 공개할 사업 정보와 문의 경로

실제 미팅 자료가 없는 수강생은 가상 사례임을 명시해 연습하며, 이를 실제 활동으로 발행하지 않는다.

## 권장 진행 시간: 45분

| 시간 | 활동 | 학습자가 완성할 내용 |
| --- | --- | --- |
| 5분 | 목표 설명·블로그 준비 | 누가 이 글을 읽고 어떤 일로 연락하기를 원하는지 정리 |
| 8분 | 사업 자료 | 양식 원본 보관, 두 사람의 서비스와 고객·공개 문의 경로 정리 |
| 5분 | 사진 드라이브 | 사진 등록, 해당 미팅의 사진 선택, 대표 사진 지정 |
| 10분 | 미팅 기록 | 대화 주제, 실제 사례, 인사이트, 각자의 홍보 포인트 입력 |
| 10분 | 글 작성 | 기본 초안 편집 또는 AI 프롬프트를 활용한 글 작성, 사진 미리보기 |
| 7분 | 공개 내용 확인·발행 기록 | 블로그에서 직접 발행 후 주소 보관 |

## 진행 질문

1. 상대방은 어떤 고객의 문제를 해결하는가?
2. 이번 대화에서 상대방의 전문성을 보여준 구체적인 사례는 무엇인가?
3. 나의 경험이나 서비스가 이 주제와 어떻게 연결되는가?
4. 이번 만남에서 내 생각이 달라진 부분은 무엇인가?
5. 실제로 합의한 다음 행동은 무엇인가? 없으면 생략한다.
6. 독자는 두 사람에게 각각 어떤 일로 연락할 수 있는가?

## 글의 구성

만남의 배경 → 상대방의 사업과 강점 → 실제 대화 → 내 사업에 연결한 인사이트와 전문성 → 기록된 후속 계획 → 두 사람의 사업 소개와 문의 경로.

대표 사진은 제목 아래, 추가 사진은 본문 뒤에 배치한다. 설명에는 확인된 이름·날짜·장소만 사용한다. 사진 속 얼굴로 신원을 판단하지 않는다.

양식에 적힌 배경과 미팅에서 실제 나눈 대화를 구분한다. 양식의 예시·빈 약속 항목·작성 지침을 미팅 사실로 사용하지 않는다. 직접 인용, 성과, 협업 약속은 새로 만들지 않는다. 아직 논의 중인 가능성을 완료된 성과로 표현하지 않는다.

## 실습 완료 기준

- 제목과 본문이 작성되어 있다.
- 해당 미팅의 사진이 한 장 이상 연결되어 있다.
- 실제 대화·사업 정보·계획 표현을 확인했다.
- 상대방과 사진 및 사업 정보의 공개 범위를 확인했다.
- 양쪽 전문성과 문의 방법이 균형 있게 담겼는지 확인했다.
- 직접 발행한 블로그의 HTTP(S) 주소를 등록했다.

시스템의 ‘발행 기록’은 사용자가 직접 등록한 결과이며, 외부 사이트의 게시 상태를 자동 검증한 표시가 아니다.

## 현재 구현 범위

- 다섯 단계의 실습 화면과 입력 안내
- PDF/PPTX 원본 보관 및 다운로드 (파일당 25MB, 임시 파일 제외)
- JPG/PNG/WebP 사진 드라이브 (파일당 10MB, 전체 자료 합계 50MB)
- 미팅별 사진 선택, 대표 사진, 사진 포함 미리보기
- 입력한 사실로 기본 초안 구성 및 편집
- 외부 AI에 사용할 작성 프롬프트 복사 (자료를 데이터로 구분하고 사실 생성 금지)
- 본문 복사, 사진 다운로드, 사진을 포함한 독립 HTML 파일 저장
- IndexedDB를 통한 현재 작성 내용·첨부·미팅 기록의 브라우저 내 저장
- 미팅별 작성 중/발행 기록 구분 및 이어서 편집

계정 인증, 외부 드라이브 연동, PDF/PPTX 자동 추출, 서버 AI 호출, 외부 블로그 자동 발행은 이 버전에 포함하지 않는다. 사용자가 자료의 공개할 핵심 내용을 직접 입력하고, AI를 쓸 경우 프롬프트를 사용하는 AI에 붙여 넣는다. 원본 파일이 자동으로 AI 서비스에 전송되지는 않는다.

브라우저의 사이트 데이터를 삭제하면 보관 자료가 지워진다. 다른 브라우저·기기·호스트에서는 공유되지 않으므로 결과물을 HTML과 사진으로 내려받아 보관한다. 공개 서비스에서 여러 회원이 사용하는 형태로 확장할 때는 사용자별 인증, 저장소와 접근 권한, 원본 추출, 실제 AI 생성, 발행 연동을 별도로 연결해야 한다.

## 검증

`node --test tests/one-to-one.test.mjs`

필수 입력 누락 시 생성 차단, 양쪽 사업 정보 반영, 목표·후속 계획의 임의 생성 방지, 안전한 발행 링크, 완료 기준 및 AI 프롬프트의 데이터 구분을 확인한다. 빌드는 `npm run build`로 검사한다.
