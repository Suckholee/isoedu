## 데이터와 권한 인계

- CRM 원본 source + companyId + externalId → crm_import_links → audit_projects → project_requirements.document_id. 원본 바이트 이관은 기존 별도 경로이며 이 기능은 이미 접근 가능한 회사/문서만 연결한다.
- company_members의 OWNER는 회사 권한 관리자다. company_consultants는 그 회사의 업무 담당 관계다. 주 컨설턴트는 다른 회사나 회사 OWNER 권한을 얻지 않는다. 일반 기업 직원의 요청을 공동 컨설턴트로 승인할 때 편집 권한 부여를 명시한다.
- 관리자의 기존 회사 편집 구성원 지정 또는 공동 담당 승인 → consultant_team → 회사 프로젝트·문서·업무의 기존 RLS. 이관 후보 지정 → 후보자 수락 → 원자적으로 주 담당 교체. 담당 해제 후 이전 profile.company_id로 접근이 복구되지 않는다.
- project_document_requests는 companyId/projectId/requestKey와 실제 보관 문서, 제출 경로/체크섬/시각, 검토자를 보관한다. 업로드 자체는 제출 완료·심사 적합 판정이 아니다. 고객은 제출, 회사 주체·승인된 컨설턴트는 보완/내부 확인. 직접 테이블 수정 불가.
- project_operations는 회사/프로젝트 및 revision으로 저장한다. 동시 수정 시 덮어쓰지 않고 재조회 안내. 견적·입금·예약을 서로 자동 완료시키지 않는다. 가예약은 미입금 상태로도 저장 가능하다.
- 저장한 심사일 → meeting-audit 업무; 차기 심사일(우선) 또는 인증 만료일 → 한 달 전 meeting-renewal-notice 업무. 고객 제출 요청/검토 → intake-* 업무. 날짜 누락은 미정이며 가짜 날짜를 만들지 않는다.
- 인증서 연결은 같은 회사의 CERT 문서만 허용한다. 기관 발급 원본을 보관하는 기능이며 플랫폼 발급이 아니다.
