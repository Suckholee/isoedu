# 공통 UX 기록

## UX-001 사이드바는 항상 접고 펼칠 수 있어야 한다

- 사용자 요구: 회사별 구비문서 설명·실습 화면처럼 작업 영역이 넓게 필요한 경우 사이드바를 접을 수 있어야 한다.
- 적용: 홈과 모든 주 메뉴 화면. 콘텐츠 스크롤과 관계없이 접기·펼치기 버튼이 도달 가능해야 한다.
- 열린 상태: 사이드바 위쪽에 접기 버튼. 닫힌 상태: 왼쪽 56px 탐색 레일에 펼치기 버튼과 메뉴 아이콘.
- 접거나 펼쳐도 회사·규격·필터·선택 문서·작성 내용은 유지한다. 콘텐츠 컴포넌트를 다시 만들지 않는다.
- 상태는 기존 `isoedu_sidebar_open` 설정으로 브라우저에 저장한다. 저장소 접근 실패 시에도 클릭 동작은 유지한다.
- 키보드: [ 또는 Ctrl/Cmd+B. 입력창·편집기에서 타이핑 중에는 동작시키지 않는다.
- 접근성: 버튼 이름, aria-expanded, 포커스 표시를 제공한다.
- 업무 데이터 저장·회사 권한·서버 상태에는 영향을 주지 않는다.

관련 기능: S05·S08·S11~S17 및 공통 탐색 셸.

검증: 주 메뉴 8개에서 접기·펼치기 및 콘텐츠 유지 확인. 새로고침 후 hydration 완료 시 접힘 복원 확인. [ 단축키 확인. 로그인 전 상태이므로 인증된 회사 데이터 편집 중 보존은 별도 검증 필요.

## UX-002 접힌 사이드바에도 메뉴 기호를 유지한다

- 열린 상태와 같은 8개 메뉴를 같은 순서의 아이콘으로 제공한다.
- 아이콘 클릭은 펼치지 않고 해당 화면으로 이동한다. 현재 메뉴는 파란 배경과 aria-current로 표시한다.
- 마우스 올림·키보드 포커스 시 메뉴 이름 툴팁을 표시하고, 각 버튼에 읽을 수 있는 이름을 제공한다.
- 펼치기 버튼을 계속 제공한다. 접힘 상태와 기존 회사·문서 컨텍스트를 유지한다.
- 데이터·권한·저장 정책 변경 없음. 공통 셸 전체에 적용한다.

검증: 접힌 상태의 메뉴 아이콘 8개 이동 및 현재 선택 표시 확인. 이동 후 접힌 상태와 펼치기 버튼 유지 확인.

## UX-003 정부지원사업 일정 전체 보기

- 기본 진입은 월간 달력. 이전·다음 달과 오늘 이동을 제공한다.
- 모집 시작일부터 마감일까지 표시하며 기간 초과 항목은 더 보기로 확인한다.
- 일정 미확인 사업은 삭제하거나 임의 날짜를 넣지 않고 별도 목록에서 모두 제공한다.
- 중앙정부/지자체와 검색 필터, 사업 상세에서 필요 서류 이동 제공. 달력 복귀 시 월·검색·분류 유지.
- 실제 공고 날짜와 최신 정보 연동 여부, 기업 자격 판별 범위를 명확히 표시한다.

## UX-004 기능마다 독립된 URL

- 메뉴는 /dashboard, /certifications, /documents, /audit-schedule, /risks, /notifications, /government-programs, /reports, /admin, /settings로 이동한다. 관리자 센터 하위 탭은 /admin?tab={members|companies|dispatch|operations|audit-logs} 및 /admin/{subtab} 경로를 지원한다.
- 정부사업 보기는 /government-programs/calendar 및 /government-programs/list. 선택 사업은 program 파라미터로 전달한다.
- 규격·문서 계층은 standard/folder 파라미터로 보존한다. 프로젝트는 /projects/{id}로 접근하며 실제 권한 있는 프로젝트만 표시한다.
- /는 공개 기업 랜딩이며 /dashboard는 로그인 후 업무 공간이다. 직접 접속·새로고침·뒤로/앞으로 가기를 지원한다. 알 수 없는 경로는 404.
- 공통 셸은 layout에서 유지해 화면 이동만으로 회사·문서 데이터 저장소를 재생성하지 않는다. 경로 변경 시 작업 영역 스크롤은 위로 이동한다.
- URL은 접근 권한을 부여하지 않는다. 기존 인증·회사 데이터 저장 경로를 유지한다.

## UX 005 참고문서 뷰어와 회사별 작성

문서 관리에서 참고 문서함으로 이동하고 선택 문서는 reference 파라미터로 직접 접근한다. 원문 열람과 회사용 초안 생성을 구분한다. 목차 후보를 확인하고 대상 회사·사업 아이템을 정한 후 초안을 미리본다. 타 회사 사실·수치를 복사하지 않는다. 저장 실패를 완료로 표시하지 않는다. 비PDF 본문 뷰어는 원본 배치와 다름을 명시한다.

## UX 006 거래처별 드라이브

문서 관리의 첫 화면은 거래처 폴더다. 거래처→하위 폴더→파일로 탐색하고 현재 경로를 항상 표시한다. 폴더/파일/휴지통은 URL로 구분한다. 참고 활용은 파일별 작업으로 제공한다. 이름변경·이동·업로드·복원은 실제 저장 후 완료를 표시한다. 원본 PDF·이미지 보기와 추출 본문을 구별한다. 기존 원본을 보존하고 삭제는 휴지통 이동으로 처리한다. TXT/MD 초안 편집은 이전 내용을 별도 보관한다. 현재 로컬 단일 사용자 저장과 클라우드 공유를 혼동하지 않는다.

## UX-007 피터의 정보 밀도 기준

사용자 지시(2026-10-18): 기한 지남·오늘 마감 같은 단순 건수에 큰 카드나 넓은 영역을 사용하지 않는다. 숫자는 필터/탭 옆의 작은 배지 또는 한 줄 요약으로 표시한다. 핵심 업무 목록·문서·실제 작업 영역을 우선 배치한다. 단순 집계용 큰 KPI 카드/과도한 빈 여백을 기본 디자인으로 만들지 않는다. 내 업무는 중복 요약 카드3개를 제거하고 기간 필터 옆에 숫자를 통합한다. 기존 필터 동작·URL·저장·권한은 유지한다.


## UX-로고 홈 이동
열린 사이드바의 어니스톤 로고와 접힌 레일의 방패 로고는 /dashboard 내 업무 홈으로 이동한다. 키보드 버튼 이름은 어니스톤 홈으로 이동. 회사·필터·접힘 상태를 유지한다. S05 공통 탐색 규칙.


## UX-MODAL-001 모든 모달의 기본 닫기 동작
- 모든 모달·배경이 있는 상세 패널은 Esc 또는 바깥 배경 여백 클릭으로 닫는다. 모달 내부 클릭은 유지한다.
- 여러 모달이 열려 있으면 가장 위의 모달만 닫는다. IME 조합 중 Escape는 입력 처리를 우선한다.
- 닫기는 기존 X/취소와 같은 콜백을 사용하며 저장·삭제·제출을 실행하지 않는다. 작성 상태는 기존 화면의 상태 관리 기준을 따른다.
- 새 모달은 src/components/ui/ModalLayer.jsx를 사용한다. 컴포넌트별 중복 Escape 리스너는 추가하지 않는다.
- 닫힌 뒤 기존 포커스 요소가 남아 있으면 복귀한다. 회사·규격·필터·사이드바 상태를 임의 초기화하지 않는다.
- 적용 범위: 14개 컴포넌트19개 오버레이. S02·S03·S05·S11·S15~S17 공통 UX. 네 가지 닫기/스택 테스트 및 경로회귀3개 통과.


## UX-CONTENT-001 실제 내용이 화면의 주 영역이어야 한다
- 제목·안내문·탭·기능 버튼을 감싼 과도한 여백과 중복 헤더로 내용 영역을 줄이지 않는다. 요약보다 실제 업무 내용의 가시 면적을 우선한다.
- 문서 열람은 열자마자 집중 열람 화면으로 제공한다. 문서함 제목·설명·탭·회사 경로·문서 개수는 열람 화면 위에 반복하지 않는다.
- 상단 도구막대는 데스크톱 기본48px 내외로 유지하고 파일명·목록 복귀·원본 다운로드·본문 전환·닫기만 제공한다. 긴 파일명은 말줄임과 툴팁으로 처리한다. 작은 화면에서는 버튼을 줄바꿈하되 본문을 스크롤 밖으로 밀어내지 않는다.
- 문서/본문 영역은 남은 뷰포트 높이를 모두 사용한다. 모달 상위 페이지를 스크롤해야 문서가 나타나는 구조를 피한다. iframe 내부와 추출 본문 모두 자체 스크롤을 사용한다.
- 닫으면 기존 거래처·목록 상태로 돌아가며 UX-MODAL-001의 Esc/바깥 클릭을 유지한다. 원본 저장·서명URL·회사 권한은 변경하지 않는다.
- 적용: S11·S16·S17 CloudFileViewer. CSS 모듈과 body portal로 목록 레이아웃과 분리한다.


## UX-REGISTER-001 유형별 관리 화면은 대장형 표를 우선
ISO 인증 관리는 큰카드·장식요약보다 규격탭·연결상태탭·열필터·행별동작으로 구성한다. 인증서/매뉴얼/절차서/지침서/양식·기록 유형을 구분하고 내용영역 안에서 표헤더를고정한다. 문서연결상태와 실제작성/승인·심사적합상태를 혼동하지않는다. 계정표시는 상단메뉴로통일하고 사이드바하단의 중복 로그인필요 안내는표시하지않는다.


## UX-HEADER-001 계정 헤더와 본문 작업 영역 분리
거래처·계정 제어는 본문 바깥의 상단행에 배치한다. 절대배치로 업무 추가·프로젝트 버튼 위를 덮지 않는다. 좁은 화면에서 칩 이름은 말줄임하고 작업제목/버튼은 줄바꿈한다. 사이드바 접기·펼치기 및 회사/문서/필터 상태를 유지한다.


## UX-PUBLIC-GOV-001 공개 캘린더에서 업무 준비로 연결
/와 /programs는 공개 기업 유입 경로다. 공고 열람은 로그인 전에 제공하고 관심사업/신청 준비 저장 시 로그인·대상 회사 확인으로 연결한다. 달력·목록·월·검색·분류·선택 공고를 URL에 보존하며 일정 미확인과 부분 분석을 감추지 않는다. 모바일 달력은 날짜별 건수와 선택 날짜 목록을 제공한다. 상세는 Esc/여백으로 닫고 로그인 취소 후에도 공고 선택을 유지한다. 회사 자격·공식 접수·마감 확정을 공고 열람과 혼동하지 않는다. 기존 공통 업무 셸과 회사 권한은 유지한다.


## UX-DOCUMENT-PANEL-001 문서별 주소와 작업 패널
사용자 지시(2026-11-05): 세부 문서는 직접 접속 가능한 하위 주소를 제공하고 ChatGPT처럼 목록과 작업 패널을 우선한다. 기업 준비는 왼쪽 목록·오른쪽 작성/검토 패널, 좁은 화면은 상단 문서 목록, 표는 가로 스크롤. 저장·다운로드는 하단 동작으로 유지. 준비 작업 원본 뷰어는 inline 패널이며 다른 기존 화면의 모달을 전역 변경하지 않는다. URL만으로 권한을 부여하지 않는다. S05·S11~S17, UX-001 유지.


## UX-DOCUMENT-DENSITY-001 상단은 한 줄, 실제 문서가 먼저
사용자 지시(2026-11-05): 문서 작업에서 제목·설명·카드 제목·설정 요약을 여러 줄로 쌓아 위쪽 여백을 만들지 않는다. 계정·설정·검토·저장을 상단 약56px 도구막대로 모으고 목차·양식·AI 대화가 바로 시작한다. 설정·검토·이력은 필요할 때 패널로 펼친다. 양식과 대화는 남은 높이를 사용하고 자체 스크롤을 제공한다. 사이드바 접기/펼치기·문항 이동 시 회사·문서·작성 내용·임시 대화를 보존한다. 좁은 화면은 도구를 줄바꿈하고 목차를 가로 목록으로 제공한다. S05·S11~S17, UX-001/UX-CONTENT-001/UX-HEADER-001 유지.

## UX-FORM-INLINE-001 양식 칸에서 직접 수정
사용자 지시(2026-11-05): 별도 전체 본문 편집으로 전환하지 않아도 실제 양식의 기본정보/본문 칸에서 직접 편집한다. 입력 가능 칸은 hover/focus와 짧은 직접 수정 안내를 제공한다. 미저장 변경을 표시하며 저장 전 다운로드는 차단한다. 회사 원장과 문서별 표시 기본정보를 구분하고 미입력 정보를 지어내지 않는다. 저장본은 같은 값으로 재조회·이전 수정본·Word에 전달한다. 특허 공개자료는 선택 후 참고자료에만 추가하고 회사 보유 여부로 자동 전환하지 않는다.


## UX-SOURCE-PANEL-001 자료를 읽고 빈 정보만 묻기
사용자 지시(2026-11-05): 기존 계획서·회사 자료를 내 자료 패널에서 올리고 원문 분석 진행/중지/이어가기와 쪽별 표·그래프·판독 불확실성을 확인한다. 문서는 옆 패널의 실제 항목 칸에 출처와 함께 반영한다. 기본은 빈칸만 채우고 작성된 내용의 자료 추가는 명시적으로 선택한다. 완료된 분석은 새로고침 후 이어 쓰고, 미저장 반영본·기본정보를 대화가 보존한다. 제공된 정보는 재질문하지 않고 부족한 항목만 묻는다. 반영과 검토 저장·공식 제출을 구분한다. 큰 업로드를 화면 전체 모달로 가리지 않으며 상단 도구막대/문서별 주소/사이드바 상태를 유지한다.
