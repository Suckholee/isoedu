# 공통 UX 기록

## UX-001 사이드바는 항상 접고 펼칠 수 있어야 한다

- 사용자 요구: 회사별 구비문서 설명·실습 화면처럼 작업 영역이 넓게 필요한 경우 사이드바를 접을 수 있어야 한다.
- 적용: 홈과 모든 주 메뉴 화면. 콘텐츠 스크롤과 관계없이 접기·펼치기 버튼이 도달 가능해야 한다.
- 열린 상태: 사이드바 위쪽에 접기 버튼. 닫힌 상태: 왼쪽 56px 탐색 레일에 펼치기 버튼과 메뉴 아이콘.
- 접거나 펼쳐도 회사·규격·필터·선택 문서·작성 내용은 유지한다. 콘텐츠 컴포넌트를 다시 만들지 않는다.
- 상태는 기존 `isoedu_sidebar_open` 설정으로 브라우저에 저장한다. 저장소 접근 실패 시에도 클릭 동작은 유지한다.
- 키보드: [ 또는 Ctrl/Cmd+B. 입력창·편집기에서 타이핑 중에는 동작시키지 않는다.
- 접근성: 버튼 이름, aria-expanded, 포커스 표시를 제공한다.
- 업무 데이터 저장·회사 권한·서버 상태에는 영향을 주지 않는다.

관련 기능: S05·S08·S11~S17 및 공통 탐색 셸.

검증: 주 메뉴 8개에서 접기·펼치기 및 콘텐츠 유지 확인. 새로고침 후 hydration 완료 시 접힘 복원 확인. [ 단축키 확인. 로그인 전 상태이므로 인증된 회사 데이터 편집 중 보존은 별도 검증 필요.

## UX-002 접힌 사이드바에도 메뉴 기호를 유지한다

- 열린 상태와 같은 8개 메뉴를 같은 순서의 아이콘으로 제공한다.
- 아이콘 클릭은 펼치지 않고 해당 화면으로 이동한다. 현재 메뉴는 파란 배경과 aria-current로 표시한다.
- 마우스 올림·키보드 포커스 시 메뉴 이름 툴팁을 표시하고, 각 버튼에 읽을 수 있는 이름을 제공한다.
- 펼치기 버튼을 계속 제공한다. 접힘 상태와 기존 회사·문서 컨텍스트를 유지한다.
- 데이터·권한·저장 정책 변경 없음. 공통 셸 전체에 적용한다.

검증: 접힌 상태의 메뉴 아이콘 8개 이동 및 현재 선택 표시 확인. 이동 후 접힌 상태와 펼치기 버튼 유지 확인.

## UX-003 정부지원사업 일정 전체 보기

- 기본 진입은 월간 달력. 이전·다음 달과 오늘 이동을 제공한다.
- 모집 시작일부터 마감일까지 표시하며 기간 초과 항목은 더 보기로 확인한다.
- 일정 미확인 사업은 삭제하거나 임의 날짜를 넣지 않고 별도 목록에서 모두 제공한다.
- 중앙정부/지자체와 검색 필터, 사업 상세에서 필요 서류 이동 제공. 달력 복귀 시 월·검색·분류 유지.
- 실제 공고 날짜와 최신 정보 연동 여부, 기업 자격 판별 범위를 명확히 표시한다.

## UX-004 기능마다 독립된 URL

- 메뉴는 /dashboard, /certifications, /documents, /audit-schedule, /risks, /notifications, /government-programs, /reports, /settings로 이동한다.
- 정부사업 보기는 /government-programs/calendar 및 /government-programs/list. 선택 사업은 program 파라미터로 전달한다.
- 규격·문서 계층은 standard/folder 파라미터로 보존한다. 프로젝트는 /projects/{id}로 접근하며 실제 권한 있는 프로젝트만 표시한다.
- /는 /dashboard로 이동한다. 직접 접속·새로고침·뒤로/앞으로 가기를 지원한다. 알 수 없는 경로는 404.
- 공통 셸은 layout에서 유지해 화면 이동만으로 회사·문서 데이터 저장소를 재생성하지 않는다. 경로 변경 시 작업 영역 스크롤은 위로 이동한다.
- URL은 접근 권한을 부여하지 않는다. 기존 인증·회사 데이터 저장 경로를 유지한다.

## UX 005 참고문서 뷰어와 회사별 작성

문서 관리에서 참고 문서함으로 이동하고 선택 문서는 reference 파라미터로 직접 접근한다. 원문 열람과 회사용 초안 생성을 구분한다. 목차 후보를 확인하고 대상 회사·사업 아이템을 정한 후 초안을 미리본다. 타 회사 사실·수치를 복사하지 않는다. 저장 실패를 완료로 표시하지 않는다. 비PDF 본문 뷰어는 원본 배치와 다름을 명시한다.

## UX 006 거래처별 드라이브

문서 관리의 첫 화면은 거래처 폴더다. 거래처→하위 폴더→파일로 탐색하고 현재 경로를 항상 표시한다. 폴더/파일/휴지통은 URL로 구분한다. 참고 활용은 파일별 작업으로 제공한다. 이름변경·이동·업로드·복원은 실제 저장 후 완료를 표시한다. 원본 PDF·이미지 보기와 추출 본문을 구별한다. 기존 원본을 보존하고 삭제는 휴지통 이동으로 처리한다. TXT/MD 초안 편집은 이전 내용을 별도 보관한다. 현재 로컬 단일 사용자 저장과 클라우드 공유를 혼동하지 않는다.

## UX-007 피터의 정보 밀도 기준

사용자 지시(2026-10-18): 기한 지남·오늘 마감 같은 단순 건수에 큰 카드나 넓은 영역을 사용하지 않는다. 숫자는 필터/탭 옆의 작은 배지 또는 한 줄 요약으로 표시한다. 핵심 업무 목록·문서·실제 작업 영역을 우선 배치한다. 단순 집계용 큰 KPI 카드/과도한 빈 여백을 기본 디자인으로 만들지 않는다. 내 업무는 중복 요약 카드3개를 제거하고 기간 필터 옆에 숫자를 통합한다. 기존 필터 동작·URL·저장·권한은 유지한다.


## UX-로고 홈 이동
열린 사이드바의 어니스톤 로고와 접힌 레일의 방패 로고는 /dashboard 내 업무 홈으로 이동한다. 키보드 버튼 이름은 어니스톤 홈으로 이동. 회사·필터·접힘 상태를 유지한다. S05 공통 탐색 규칙.


## UX-MODAL-001 모든 모달의 기본 닫기 동작
- 모든 모달·배경이 있는 상세 패널은 Esc 또는 바깥 배경 여백 클릭으로 닫는다. 모달 내부 클릭은 유지한다.
- 여러 모달이 열려 있으면 가장 위의 모달만 닫는다. IME 조합 중 Escape는 입력 처리를 우선한다.
- 닫기는 기존 X/취소와 같은 콜백을 사용하며 저장·삭제·제출을 실행하지 않는다. 작성 상태는 기존 화면의 상태 관리 기준을 따른다.
- 새 모달은 src/components/ui/ModalLayer.jsx를 사용한다. 컴포넌트별 중복 Escape 리스너는 추가하지 않는다.
- 닫힌 뒤 기존 포커스 요소가 남아 있으면 복귀한다. 회사·규격·필터·사이드바 상태를 임의 초기화하지 않는다.
- 적용 범위: 14개 컴포넌트19개 오버레이. S02·S03·S05·S11·S15~S17 공통 UX. 네 가지 닫기/스택 테스트 및 경로회귀3개 통과.
