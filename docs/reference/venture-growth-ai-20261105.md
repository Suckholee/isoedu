## 작성 구조와 유형 구분

혁신성장은 신규(창업3년 미만/이상 평가 구분)와 재확인을 구분한다. 기업 형태와 업력, 보유 조직·실적에 따라 증빙 적용 여부를 확인한다. 공식 온라인 입력의 글자 수 제한은 공개 PDF에서 확인하지 못해 임의로 공식 제한을 정하지 않았다. 앱의 입력 제한은 서비스 처리 한도다.

사업계획서 전체13개: 개발 배경·필요성 / 솔루션 소개 / 기술개발 / 목표시장·고객 / 경쟁사 / 시장진입·확대 / 자금조달 / 팀 / 연구개발비 / 기술개발 실적 / 지식재산권 / 협업 / 사업성과. 마지막 사업성과는 재확인 기업용이다. 기존19쪽 안내의7개 서술 항목만으로 전체 양식이라고 표시하지 않는다. 원클릭 생성 대상은 사업계획서와 그 중 개발·인력·자금 항목을 사용하는 기술개발 추진계획서다. 후자는 준비용 구성이지 별도 공식 지정서식이 아니다.

매출·비용·인력·특허·고객·투자·협약 등 확인되지 않은 사실은 `[확인 필요]`로 남긴다. 제안은 `[계획안]`, 시험 데이터는 가상 기업임을 유지한다. 공식 자료의 작성 예시 숫자를 회사 실적으로 가져오지 않는다.

## 제출·현장 확인 목록

8개 기본 서류 범주는 중소기업확인서, 사업자등록증, 법인등기부, VAT증명, 재무제표/감사보고서, 고용보험 취득자명부, 4대보험 명부, 주주명부다. 법인 서류는 법인 해당 시로 표시한다. VAT·재무·고용 이력은 최근3개년 또는 업력 내 자료를 확인한다. 등기부·4대보험·주주명부·연구조직 인정서는 안내의2주 조건을 표시한다. 고용 이력은 각 연도12월 말일 기준이다.

추가 증빙은 대표자 경력·국가기술자격, 공인 연구개발조직, 연구·인력개발비 사전심사 통지, 재확인 시 선택한 수출실적이다. 이노비즈는 현재 공식 웹 목록에 있지만2026 가이드북의 추가서류 표에는 없어 기관 확인 대상으로 표시한다. 현장 확인 자료는 내부 연구조직/업무분장, 기술인력 증빙, R&D 실적, IP, 협업, 서비스 지표를 해당 시 준비한다.

앱의20개 행은 경력/자격 분리 및 현장 확인 항목을 포함한 준비 목록이며 전부 필수라는 뜻이 아니다. 사업계획서는 위 작성 영역에서 관리하고 발급서류 업로드 행으로 위장하지 않는다. 기존9개 요청의 상태·문서 연결·날짜 정책은 보존하고 누락11개만 기존 RPC로 추가했다. 표시 안내는 최신 공식 자료를 우선한다. 새 항목에는 기존 노션 자동기간 판정 규칙을 임의로 만들어 붙이지 않으며, 기간 자동검사 범위 확대는 별도 작업이다. 가상 프로젝트의 정기검사 비활성 상태를 유지한다.

## 실제 연결과 데이터 계약

S02 로그인·S03 회사 → S07 `VENTURE_GROWTH` 프로젝트 → S12 공식 기준 → S13 사업 설명/확인 사실/최대5개 같은 회사 참고 문서 → S14 실제 OpenAI Responses 호출 → S15 본문·AI 질문·검토 메모 → S17 회사 문서와 수정 이력 → B04/S19 Word 내보내기·기업 직접 온라인 신청 준비.

`/api/venture-documents`는 로그인 쿠키의 사용자 검증, 프로젝트 RLS, `can_edit_company`, 신청 유형과 참고 문서의 동일 회사 범위를 확인한다. 관리자 키를 쓰지 않는다. 서버 전용 AI 키는 사용자가 지정한 기존 프로젝트 설정에서 복사했고 브라우저 코드·문서·로그에는 넣지 않았다.

전달: `company_id`, `projectId`, `documentId`, 입력 해시·입력 스냅샷, 참고 문서 ID/본문/updated_at, 기준 version/url/SHA-256(원본 manifest 연결), 모델·응답ID·사용량, 생성 상태·시도수·실패 사유, `revisionNo`, 이전 본문/검토 기록/시각/작성자. 문서 기본행에 `content_draft`·`DRAFT/REVIEW`를 실제 저장한다. S17 이력은 생성 문서의 `metadata.ai.history`에 보관하며, 원본 파일용 `document_versions`의 파일 경로를 허위로 만들지 않는다.

생성 요청 UUID를 먼저 예약하여 같은 요청 재전송은 기존 결과를 반환한다. 처리 중 요청은 중복 생성하지 않으며130초 뒤 명시적 재시도가 가능하다. 요청당 최대3시도, 새 초안은 회사당 시간당10개 조회 한도를 둔다(엄격한 분산 과금 한도는 아님). 실패 시 원래 입력·실패 상태를 보존하고 예시 본문으로 대체하지 않는다. 수정은 `updated_at` 비교 후 이전 내용을 함께 저장하여 충돌을409로 알린다. 최대30개 수정 이력을 보존한 뒤 새 문서로 이어가도록 안내한다.

AI 응답은 문항 순서/ID/본문 크기를 검증한다. 원본 PDF 전체를 모델이 자동 분석했다고 표시하지 않으며 사용자가 선택한 저장 본문만 최대4만자로 전송한다. 외부 문서 지시를 명령으로 취급하지 않도록 시스템 지침을 분리한다. 질문·점검은 AI 안내로, 사용자의 검토 체크는 내부 검토 기록으로 보관하며 공식 승인 상태로 올리지 않는다.

- 자동검증: 기존148개+AI/API5개+DB/RLS1개 =154개. 비로그인·다른 회사·읽기전용·참고 문서 범위, 입력/출력 검증, 제공자 실패·거절·불완전응답, 중복 요청·재시도, 수정충돌·이력, 실제 마이그레이션의 회사 RLS 검증. 최종 전체 실행·빌드 결과는 기능 레지스트리와 연결표에 기록.

적용 범위는 로컬 앱+연결된 운영 회사 저장소이다. 공개 사이트 배포, 공식 사이트 자동 제출, 발급 증명서 생성, 기관 심사·인증 발급은 수행하지 않았다. 회사 실제 사업정보·실적이 없어 저장본은 기능 확인용 가상 초안이다.
